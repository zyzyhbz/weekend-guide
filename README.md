# 🧭 周末去哪儿 · 城市探索指南

> 一个把「周末到底去哪」从**信息检索问题**变成**决策问题**的产品雏形。

**在线访问：** https://zyzyhbz.github.io/weekend-guide/

---

## 这是什么

大学生周末的困境不是「没有活动」，而是：

> 信息分散在 5 个 App、受天气影响大、预算不透明、人数影响体验、选择困难、凑不齐人。

本产品把这些卡点逐个拆解，最终收敛成一句承诺：

**告诉我们你的偏好、天气、预算和人数，直接给你一份能照着走的周末方案。**

## 核心功能

| 模块 | 解决什么 | 关键设计 |
|---|---|---|
| 🧭 **探索** | 决策前：去哪 | 偏好 / 天气 / 预算 / 人数四维输入 → 输出 **3 个性格不同**的可执行方案 |
| 👥 **组队** | 决策中：和谁去 | 方案一键转招募卡（可复制文案 + Canvas 生成图片），带成行进度 |
| 📌 **打卡** | 决策后：值不值 | 记录实际花费 / 耗时 / 评分，沉淀个人城市足迹 |
| 📝 **攻略** | 下一轮决策 | 只讲官方不会说的：几点去、坑在哪、隐藏机位 |
| 💡 **设计** | — | 产品推导过程说明（痛点 → 决策的映射表） |

## 每个方案包含

- **匹配理由**（绿标）与**风险提示**（黄标）——推荐系统不该是黑箱
- **时间轴**：出发 → 抵达 → 主线体验 → 补给 → 返程，带通勤时间估算
- **花费拆解**：活动 + 餐饮 + 交通逐项列清，明确告诉你超没超预算、能省多少
- **出发清单**：随天气动态生成（防晒 / 带伞 / 防风 / 结伴提醒）
- **顺路加餐**：同片区可延长的第二个点位，不用另外找地方
- **一键招募文案**：含时间、地点、人均、还差几人，直接丢进群里

## 推荐算法

不用黑箱模型，用**可解释的加权打分 + 采样**：

1. **硬约束过滤** —— 时长塞不进时间窗、极端天气下的纯户外、超预算 1.5 倍、超出通勤范围 → 直接出局
2. **九维加权打分** —— 偏好命中、天气适配、预算契合、人数契合、时间窗契合、通勤成本、口碑质量、体力匹配、稀缺性
3. **Softmax 采样** —— 同样输入点两次不会给完全一样的结果（周末去哪本来就没有唯一正解）
4. **MMR 多样性重排** —— 保证三个方案性格不同，不会全是美术馆
5. **可解释性输出** —— 每一分都能对应到界面上的一句话

每个活动自带**天气敏感度模型** `{rain, hot, cold, wind}`，所以「下雨天推荐去哪」不是拍脑袋，而是算出来的。

## 技术实现

- 纯前端静态站点，**原生 ES Module，零构建、零依赖、零后端**
- 天气数据来自 [Open-Meteo](https://open-meteo.com)（免费、无需 API Key、支持 CORS），拉取未来 7 天逐小时预报并按时间窗聚合
- **容错设计**：天气接口异常时自动降级为演示模式并明确标注，页面永不白屏
- 组队与打卡数据存于 `localStorage`，本地优先，无隐私顾虑
- 部署于 GitHub Pages，域名长期稳定、公开可访问

```
├── index.html          页面结构
├── css/style.css       设计系统
└── js/
    ├── data.js         活动库（6 城 65 个真实场所/常设活动）+ 餐饮点 + 路线模板
    ├── weather.js      Open-Meteo 接入 + 天气画像聚合 + 降级兜底
    ├── recommend.js    推荐引擎（打分 / 采样 / 多样性重排 / 方案构建）
    ├── guides.js       攻略种子内容
    ├── about.js        产品设计说明
    └── app.js          应用主控
```

## 数据说明

活动库中的场馆与地标均为**真实存在的常设文化空间**（海上世界文化艺术中心、广东省博物馆、景山公园、西岸美术馆、良渚古城遗址公园、东郊记忆等），活动形态以常设展览 / 周期性市集 / 经典徒步路线为主，**不随时间过期**。评分与人均花费为演示样例值，攻略内容为示例 UGC。
